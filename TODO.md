# TODO

- Full-text session search. The sidebar search matches only a session's name, directory and first user message, and of a first message whose entry is over 256 KB only the first 8 KB, which the gateway keeps so a huge one cannot push the session index over its memory bound. Pi's `/resume` picker also matches the session id and the text of every user and assistant message, with fuzzy tokens, `"phrases"` and `re:` patterns. Matching it means indexing message text in the gateway, which costs memory.
- A way into the Ctrl+K palette without a keyboard, such as a touch button. It needs mockups and a choice of where it goes.
- Personal skills per user in multi-user mode. All users share the gateway's skills. Passing a user's own skills to Pi with `--skill` is not enough: a shared skill with the same name wins over one passed that way, and the subagent extension starts subagents without the flag.
- Fill in the Environment dialog's GitHub variables from a token, or import the `gh` login from the desktop app's computer. The dialog's GitHub row only adds a block of empty variables, which the user fills in by hand, with the name and email twice. Filling in the name and email means asking GitHub's API who the token belongs to, and importing a login needs the desktop app, because a browser cannot read it.
- A Gripi-owned live event model. The browser still parses Pi's events, live snapshots, model settings, fork messages and trees, which the server passes through as opaque JSON (`docs/architecture.md`), and it repeats in JavaScript the projection Go already does for history. Translating Pi's events in the adapter into a few typed events built by the same Go projection would remove the duplicate, which has drifted in edge cases such as tool-argument JSON and timestamps.
- Keep slow Markdown images from popping in. A streamed reply waits at most a second for an image, so a slower one still appears at once and pushes the text below it down.
- Carry the rest of an unsaved session over a restart for changed environment variables. The new Pi process gets only the model, thinking level and name: the output of `!` commands run before the change leaves Pi's context, and a session forked from its first message loses its link to its parent. Pi offers no way to hand them to a new process without Gripi writing Pi's session file.
- Keep a pending session's name in its header. Shortly after `/name`, the header of a session Pi hasn't saved yet goes back to "New session (pending first assistant response)", because the server shows that fixed title until the first reply.
- Clear the composer after a reload mid-command. Reloading while a `!` command runs puts the submitted command back in the composer.
- Pi output lines over 65 MB. The RPC client stops reading when one of Pi's events or responses, such as `message_end`, `tool_execution_end` or `get_entries`, is over 65 MB, so an entry that large written by the gateway's own Pi ends its client and the session asks to be taken over. Handling it means streaming such lines like the session index does, keeping only what the gateway uses.
- Keep the updater tests off the repository's own git config. `gitRun` and `gitOutput` in `internal/update` pass on the environment, so running `mise run test` from `git rebase -x` or a git hook, which set `GIT_DIR`, rewrites the repository's `core.bare` and `user.*` and commits to it.
- Hermes follow-ups (the experimental `GRIPI_HERMES`). Gripi doesn't yet choose Hermes's model or reasoning effort, rename, delete, fork or tree its sessions, or show its plan updates; ACP has no methods for some of these. The composer waits while Hermes works, though Hermes would take another message as a correction of the turn. Hermes's slash commands reach the command palette but not the composer's `/` list. A Hermes session that other ACP clients continue isn't marked unread, and one that another client has open isn't hidden as Pi CLI sessions are. Changed variables wait until no other Hermes session is open, because all of them share one process. An edit's diff shows the lines between the shared start and end, not a real diff. A session that another ACP client continues keeps showing the conversation that Gripi's Hermes loaded, until that Hermes restarts. A permission dialog stays open in a browser after Hermes stopped waiting or another browser answered, because the page doesn't poll while a dialog is open; Pi's extension dialogs do the same. A Hermes that stops reading its input would hold a write to it, and with it Stop, until the process exits. A message of only images loses them from the conversation once Hermes restarts, because Hermes saves it as `[Image attachment]`, which no longer matches the images Gripi recorded for the empty message. Hermes's history has no timestamps, so after a reload an image also shows on the first message with the same text, which may be an earlier one sent without it. An image that Hermes shares shows only while its file exists, because Gripi reads it from disk rather than keeping a copy.
- Voice conversation follow-ups. Talk over Hermes's work while the message that started it is still on its way to Hermes, such as while Hermes starts, is sent before Hermes has stopped, so Hermes refuses it and the call asks you to say it again. A reply is spoken once it has ended, not while it streams. Hermes Desktop's echo guard is missing. On an iPhone a call stops while the screen is off, which only a native app could avoid. A Hermes session started by voice is titled after the voice prefix until Hermes's model-made title replaces it, because Hermes titles it from the message as sent.
